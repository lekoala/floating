Scroll tracking: @lekoala/floating vs Tippy

Five surfaces are pinned to five neighbouring buttons and left open. Scroll, and compare how tightly each one stays glued to its button. Flip and shift are disabled everywhere, so the only thing being compared is tracking. The last one is a control: the current engine, deliberately held back by one frame, so the table shows what a frame of latency is worth in pixels.

Drift is how far the surface-to-reference offset has moved away from its offset at rest, sampled once per frame in a task posted from requestAnimationFrame so it observes the frame that was just rendered. Frames where the reference is off screen are not counted: reposition() declines those by contract. Read the numbers against the control row, not in absolute terms. A busy main thread is what turns latency into visible drift, so the checkbox burns 40 ms per frame; on a phone the page usually supplies that by itself.
